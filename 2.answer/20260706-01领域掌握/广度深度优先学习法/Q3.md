# 问题

```
如何利用大模型帮我实现这个目标，我的想法是让大模型帮我做文档笔记，遇到疑问点，让大模型在文档笔记中补充，这样经过多轮次对话，不断完善自己在新领域的知识体系
```

# 先纠正一个默认假设

你的设想是：大模型把内容写进文档笔记，遇到疑问再让它补充。这个模式本身有三个问题：

1. **顺从倾向**：你说什么，它顺着你的方向说；你理解偏了，它帮你把偏差写得更像真的。
2. **错误进入文档后反而固化**：一旦进了文档，就变成你后面的“事实”，越补越难纠正。
3. **内容越补越乱**：多轮追加会让文档失去检索性，最后是一堆你不再打开的长段落。

正确的分工是：**你是主编，大模型只做具体工作：测绘（广度）、攻坚助手（深度）、审稿人（质检）。文档是唯一事实来源，它的所有输出都必须经过「回填校验」才能进入文档。**

# 一、文档结构（分三层，不要做成一个大文件）

```
knowledge/<领域>/
├── 00-MAP.md          # 知识地图：节点清单 + 状态标签 + 依赖边
├── 01-QUESTIONS.md    # 疑问队列（带优先级、来源、状态）
├── 02-SOURCES.md      # 可信来源清单（教材/论文/官方文档 + 章节页码）
├── concepts/
│   ├── 梯度下降.md
│   └── ...
└── CHANGELOG.md       # 每次回填：日期、来源、改了什么、置信度
```

分层的理由：MAP 是广度层，卡片是深度层，QUESTIONS 是**切换触发器**，SOURCES 是防止大模型编造的基准。用 git 管理，每次回填一个 commit，出错就能回滚——你本来就熟悉，成本很低。

# 二、卡片模板（整套方法的核心）

每个概念一张卡片，字段固定，**缺字段就说明还没学完**：

```
# 概念名
status: 🗺️        # 🗺️已测绘 / ⛏️攻坚中 / ✅本轮达标 / 📌后置
depends_on: [A, B]
used_by: [C]

## 一句话定位
它解决什么问题、属于哪个子模块（不超过两行）

## 定义（须有出处）
原文 + 出处（书名+章节/页码）

## 我的复述          ← 必须手写，禁止复制模型原文
## 一个正例
## 一个反例 / 失效场景
## 边界条件 / 前提假设
## 和邻居的关系
- 与 A：...
- 与 B：...
## 未解决的疑问
→ 指向 01-QUESTIONS.md 某条
## 自测题
3 道，至少 1 道自己出
```

**关键要求：`我的复述` 必须自己写。**模型只允许在「定义/出处/反例候选/自测题」出草稿。这一条能挡掉大部分“以为自己懂了但其实没会”的情况——很多人笔记失败，是因为笔记里全是模型的字，没有自己的字。

# 三、四个能直接复制的提示词

每个提示词都带**输出约定**：规定输出格式，让模型只提供可以粘回卡片的片段，而不是重写整篇。

### 1. 测绘（广度阶段）

```
角色：你是 <领域> 的课程设计者，不是讲师。
任务：为 <领域> 输出一张概念骨架，供零基础者建立地图。

输出格式（严格）：Markdown 表格，列 =
[概念 | 一句话定位 | 前置依赖 | 被谁依赖 | 是否枢纽(高/中/低) | 建议顺序]

约束：
- 只列 15~25 个概念，只要主干，不要边角
- 每格不超过 20 字，禁止解释细节、禁止列公式
- 依赖关系必须真实存在，不确定写"待确认"
- 最后单独一段：你对该领域本身的盲区——你不确定它包含什么、可能整块漏掉什么

不要输出学习建议、不要鼓励我。
```

最后那段最有用：让模型**主动说明它不确定的地方**，比看它自信地列举可靠得多。

### 2. 攻坚（深度阶段）

```
角色：严格的教材编写者 + 审稿人。
目标概念：<X>
本轮目标：<可终止目标，如"能推导A / 能写代码B / 能判断C场景会失效">

输出六段，标注 [定义][原理][正例][反例][边界][常见误解]

硬约束：
- 定义必须给可查来源（书名+章节）；查不到就明确写"未找到权威出处，以下为常见说法"
- 每个公式给成立条件，不许裸写
- 反例必须具体可算，不许"某些情况下会失效"
- 每段标置信度：高（教科书共识）/ 中（主流但有争议）/ 低（我的推断）
- 禁用"显然""众所周知""一般来说"
```

### 3. 答疑回填（就是你设想的那个环节，但加了约束）

```
下面是我的笔记卡片。<粘贴卡片>
疑问：<...>

要求：
1. 先分类：该疑问属于 (a) 当前概念的细节 (b) 缺失的前置概念 (c) 超出本轮边界
2. 是 (b)：不要直接讲，先告诉我该补哪个前置概念、它在骨架里的位置
3. 是 (a)：只输出"待回填片段"，字段格式与我的卡片一致，可直接粘贴，不要重写整张卡片
4. 是 (c)：只输出一句话建议后置，不要展开
5. 结尾必须回答：这条补充会不会改变卡片里"一句话定位"的表述？会/不会，一句理由
```

第 5 条是**防止理解受补充影响而偏离原意触发点**：很多补充会悄悄改变概念的定位，迫使模型自己检查。

### 4. 审计（每 5~8 次回填做一次）

```
这是我的知识地图 + N 张卡片。以"找茬"模式审查：
1. 概念间是否有循环依赖、断链（依赖了地图里不存在的概念）
2. 哪些卡片的"一句话定位"互相矛盾或重叠
3. 哪些 status=✅ 的卡片，其"我的复述"实质是定义原文的同义改写
4. 按"枢纽度 × 未达标"给出下一轮最该攻坚的 3 个节点

只输出问题清单。不要给答案，不要表扬，不要总结我的优点。
```

# 四、防止大模型编造内容的三道闸

| 闸 | 做法 | 挡住什么 |
| --- | --- | --- |
| **来源闸** | 定义/公式必须填出处字段；模型给不出 → 卡片标「未验证」，禁止升级到 ✅ | 编造的定义 |
| **反向闸** | 学完一个概念，让模型扮演“用错误理解的学生”提 3 个问题，你必须答对 | 自以为懂 |
| **交叉闸** | 同一问题换**新会话**重问，答案不一致处 = 高风险区；公式自己手推一遍 | 稳定的一致错误 |

数学和 AI 基础这两个领域，反向闸和交叉闸尤其值钱——因为大模型能给出看起来合理、但细节错误的推导，而且语气很自信。

# 五、上下文管理（多轮叠加最容易出问题的地方）

大模型在长对话里会：忘记早期约定、越来越顺你的话、把之前说错的当成既定事实。对策：

- **每轮开头粘一段状态摘要**（未达标节点 + 本次目标 + 边界），不超过 200 字，不依赖模型记忆；
- **一个概念一个会话**，学完就开新的，不要在一个会话里连学十个概念；
- 每 5~8 轮做一次审计，让模型重新读整张地图；
- 让模型输出**片段/diff**，你自己 apply，永远不要让它整篇重写你的文档。

# 六、和你前面那套广度/深度切换怎么接

文档里的 status 标签就是切换开关，不用再凭感觉判断：

- 🗺️ 节点 ≥ 15 个但 ✅ 只有 1~2 个 → 广度足够了，切深度
- 答疑时模型分类为 (b) 缺前置 → 回广度补，补完再回来
- 同一细节卡住超过 2 小时且不在本轮目标内 → 标 📌 上浮
- 审计输出「矛盾/断链」 → 强制回广度重构

举个具体例子：你学梯度下降，卡片 status=⛏️，卡在「为什么学习率大会震荡」。答疑提示词会先分类——这是 (a) 当前细节（条件数/曲率），还是 (b) 前置缺失（二次型、Hessian、特征值）？如果是 (b)，模型应该拦住你，先让你去补线性代数里那块，而不是硬讲优化。

# 七、三个最常见的问题

1. **让模型“帮我整理成笔记”** → 得到的是模型的笔记，不是你的理解。整理必须在你自己这里完成，模型只提供原始材料和质疑。
2. **卡片只有定义、没有反例** → 你能在标准场景用，一变形就废。反例字段是硬指标。
3. **没有疑问队列** → 疑问散落在对话里，会话一关就没了，广度/深度之间的循环转不起来。

---

一句话：**别把大模型当老师，把它当“质量一般但很快的研究助理 + 一个不会客气的审稿人”，你自己永远是那个决定谁进文档的人。**
