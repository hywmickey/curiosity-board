# 广度深度优先学习法 · 知识库

> 先用广度测绘拿到全局地图，再用深度攻坚一口井一口井往下打；打完几口井，回到广度视角重新看地形。
> 每个领域一份独立笔记，所有文件都为「人 + LLM 协作」设计，可直接整段复制给大模型当上下文。

## 目录结构

```
knowledge/
├── README.md              ← 本文件：模板说明与上手流程
└── 你的领域名/            ← 复制一份，改成你要学的方向（如：微积分 / Go并发 / 深度学习基础）
    ├── README.md          ← 该领域的学习策略、协作分工、状态标签、入库铁则
    ├── 00-MAP.md          ← 知识地图：概念骨架、依赖关系、枢纽等级、主线顺序
    ├── 01-QUESTIONS.md    ← 疑问队列：卡点存档、分类、回填追踪
    ├── 02-SOURCES.md      ← 可信来源清单：定义/公式的追溯依据，防幻觉
    ├── 03-PROMPTS.md      ← 提示词合集：广度测绘 / 深度攻坚 / 答疑回填 / 审计
    ├── CHANGELOG.md       ← 变更流水，配合 git 回看认知演进
    └── concepts/
        └── 示例卡片.md     ← 标准概念卡模板，新建概念直接复制这个
```

## 各文件职责

| 文件 | 作用 | 什么时候更新 |
| ---- | ---- | ---- |
| `00-MAP.md` | 全局概念骨架，决定「先学什么、哪些是枢纽」 | 每轮广度测绘后；每次深度攻坚结束回填状态 |
| `01-QUESTIONS.md` | 装下中途冒出的疑问，避免打断当前攻坚 | 遇到卡点立即记录；解决后附回填位置 |
| `02-SOURCES.md` | 权威来源台账，卡片定义只认这里 | 首次收集素材时登记；发现更好的来源时替换 |
| `03-PROMPTS.md` | 四个固定提示词，保证 LLM 输出可校验 | 按需微调，改动记入 CHANGELOG |
| `concepts/*.md` | 单概念深度卡片，理解的最小单元 | 每个攻坚节点新建一张 |
| `CHANGELOG.md` | 每次实质修改留痕 | 每完成一张卡 / 一次审计 |

## 状态标签

| 标签 | 含义 |
| ---- | ---- |
| 🗺️ | 已测绘：知道定位和依赖，未深挖 |
| ⛏️ | 攻坚中：当前深度学习的唯一节点 |
| ✅ | 本轮达标：达到预设深度目标，通过自测 |
| 📌 | 后置：支线问题，暂不展开，已进疑问队列 |

## 学习循环

```
广度测绘（00-MAP） → 选枢纽 → 深度攻坚（concept 卡） → 回填地图
        ↑                                              ↓
        └──────── 审计（提示4，每 5~8 张卡） ←──────────┘
```

## 快速上手

1. **建库**：复制 `你的领域名/` 并改成真实领域名；把域内 `README.md` 的【领域名称】改成同名。
2. **测绘**：用【提示 1】跑一轮广度，把概念表填进 `00-MAP.md`，盲区写进「已知体系缺口」。
3. **定目标**：在 `00-MAP.md` 的「当前攻坚目标」只写 1 个节点，状态改 ⛏️。
4. **建卡**：复制 `concepts/示例卡片.md` → `concepts/<概念名>.md`，用【提示 2】收集素材。
5. **登记来源**：把用到的教材/文档/论文写进 `02-SOURCES.md`，拿到 S 编号。
6. **手写复述**：自己写【我的复述】和自测题，核对来源无误后状态改 ✅，`CHANGELOG.md` 记一行。
7. **处理岔路**：中途疑问用【提示 3】分类——
   - a 当前细节 → 只回填该片段；
   - b 缺前置概念 → 回 `00-MAP.md` 补广度；
   - c 超出本轮边界 → 标 📌 进 `01-QUESTIONS.md`。
8. **审计**：每完成 5~8 张卡，用【提示 4】查依赖环路、概念冲突、复述是否浮于表面。

## 一张卡片的完成标准

- 定义标注了 `02-SOURCES.md` 里的出处 ID；找不到权威出处就明确写「未验证」
- 正例、反例、边界条件齐全，反例具体到可判断
- 【我的复述】为本人手写，不是复制模型原文
- 自测题能闭卷答对
- `00-MAP.md` 对应行状态更新，`CHANGELOG.md` 有记录

## 维护约定

- 概念卡按概念命名，中文可用，避免空格和 `/`。
- 一次只攻坚一个节点；新想法先入 `01-QUESTIONS.md`，不打断本轮。
- 每次实质修改都写 `CHANGELOG.md`；commit message 建议 `概念名: 动作`（如 `梯度下降: 补反例`）。
- 若 `git status` 中文路径显示为八进制转义，执行 `git config --global core.quotePath false`。
