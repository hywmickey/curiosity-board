# Android 项目源码快速学习提示词文档

> 适用对象：有 PHP / Golang 后端开发经验，希望快速掌握 Android 项目源码语法与业务逻辑的程序员。  
> 使用方式：将本文档中的提示词复制给大模型 Agent，并按阶段逐步执行。  
> 核心思路：不要让大模型一次性分析整个项目，而是让它先做项目地图和学习路线，再按业务模块逐个分析；每个模块强制输出调用链、语法卡片、PHP/Go 类比、自测题，并引用源码路径和行号。

## 1. 总体使用策略

最有效的做法不是只写一句“帮我讲解这个 Android 项目”，而是把大模型 Agent 约束成：

**Android 架构导师 + 源码审计员 + 学习路径规划器。**

提示词中要明确：

- 你的后端背景：熟悉 PHP、Golang；
- 你的目标：掌握 Android 项目源码中的语法和业务逻辑；
- 项目材料：文件树、Gradle 配置、Manifest、关键源码；
- 输出格式：Markdown 学习文档、表格、Mermaid 图；
- 证据要求：关键结论必须引用文件路径和行号；
- 禁止行为：不要臆测不存在的类或逻辑；
- 学习节奏：先路线图，再每次只分析一个阶段或一个业务模块；
- 复习机制：每轮输出“已完成、未掌握、下一轮建议”。

推荐流程：

1. 提供项目结构和技术栈信息；
2. 让 Agent 输出学习路线图；
3. 按阶段逐轮分析；
4. 每轮只分析一个业务模块；
5. 阶段性汇总语法速查表；
6. 最后做自测、复盘和综合题。

## 2. 主提示词：先制定学习路线，不要直接讲代码

把 `[ ]` 中的内容替换为你的项目信息。建议先把项目文件树、Gradle 配置、Manifest、关键源码提供给 Agent。

```text
你是一位资深 Android/Kotlin 架构师，同时非常了解 PHP 和 Golang。现在你要作为我的私人导师，帮助我快速掌握一个 Android 项目的源码语法和业务逻辑。

我的背景：
- 我是后端程序员，熟悉 PHP 和 Golang。
- 我了解 HTTP、数据库、依赖注入、分层架构、异步/并发、ORM 等后端概念。
- 我的 Android/Kotlin/Java 基础较弱，希望你把 Android 概念类比到 PHP/Go 中解释。
- 我的目标是：先建立项目全局地图，再按业务模块阅读源码，同时掌握项目中实际用到的 Android/Kotlin/Java 语法。

项目信息：
- 项目根目录/仓库地址：[填写]
- 技术栈：[Kotlin/Java、XML/Compose、MVVM/MVI、Hilt/Koin、Retrofit、Room、协程/RxJava等，未知就写未知]
- 最低支持 Android 版本：[填写]
- 我每天可投入时间：[例如 2 小时]
- 期望周期：[例如 7 天掌握核心业务]

工作原则：
1. 严格基于我提供的文件树、配置和源码回答，不要臆测不存在的类或逻辑。
2. 所有关键结论必须引用文件路径和行号；无法确认的地方标注“需确认”。
3. 不要一次性分析整个仓库。先给路线图，再每次只处理一个阶段或一个业务模块。
4. 讲解业务逻辑时，要画出从 UI/入口到 ViewModel/UseCase/Repository/DataSource 的调用链。
5. 讲解语法时，只讲“项目中实际出现”的语法，并给出 PHP/Go 类比、Android 特有易错点、最小示例和项目中的真实用法。
6. 输出 Markdown 学习文档，使用表格和 Mermaid 图。语言简洁、可执行、可复习。
7. 每轮结束时更新“学习状态”：已完成什么、未掌握什么、下一轮建议是什么。

请先不要直接讲解代码。你需要先阅读我提供的项目结构和技术栈信息，然后输出：

D. 建议的模块分析顺序，说明为什么这样排序；
E. 建议生成的学习文档目录，例如：
   00-项目地图.md
   01-技术栈与后端类比.md
   02-Kotlin语法最小集.md
   03-启动流程与页面框架.md

   05-数据层与网络层.md
```

## 3. 每轮任务提示词：按模块渐进分析

当你确认路线图后，每轮只让 Agent 分析一个模块。模板如下：

```text
当前学习状态：
- 已学习：[填写，例如 项目地图、Kotlin 基础语法、启动流程]
- 尚未掌握：[填写]
- 本轮目标：[例如 理解“订单列表”模块的业务流程和相关语法]

现在请分析模块：[模块名，例如 登录模块/订单列表/支付流程]。
请严格基于我提供的源码，按以下结构输出学习文档：

1. 模块职责：这个模块解决什么业务问题，用户可见功能是什么。
2. 阅读顺序：先读哪些文件、后读哪些文件，为什么。
3. 入口与调用链：从 Activity/Fragment/Composable/Service/Receiver 入口开始，画出 UI -> ViewModel -> UseCase/Repository -> DataSource 的调用链，使用 Mermaid。
4. 关键类与函数：逐个解释职责、输入输出、状态变化、异常处理。
5. 涉及语法卡片：只提取本模块出现的 Kotlin/Android/Java 语法，每条包含：
   - 语法点；
   - 出现位置（文件+行号）；
   - 作用；
   - PHP/Go 类比；
   - Android 特有易错点；
   - 最小示例；
   - 本项目真实用法。
6. 数据模型与接口：请求/响应模型、数据库实体、DTO、状态类。
7. 生命周期、线程与协程：在哪些生命周期方法中触发，是否涉及主线程切换、协程作用域、Flow/LiveData、取消与异常。
8. 与 PHP/Go 的架构类比：例如 ViewModel 类似请求级状态容器，Repository 类似 DAO/Service 组合，协程类似 goroutine/async，依赖注入类似容器。
9. 常见误解：列出 3 到 5 个后端程序员容易误解的点。
10. 自测题：出 5 道题，附答案。最后给出“下一轮建议”。

要求：
- 不要编造源码中不存在的逻辑。
- 对不确定处标注“需确认：原因”。
- 所有关键结论引用文件路径和行号。
```

## 4. 语法专项提示词：建立项目专属 Kotlin/Android 语法速查表

当已经分析过 2 到 3 个模块后，让 Agent 汇总语法，避免零散。

```text
请根据我们已分析过的模块，整理一份“本项目专属 Android/Kotlin 语法速查表”。

要求：
1. 只收录项目中真实出现过的语法，不要泛泛而谈整个 Kotlin 语言。
2. 按使用频率和重要程度排序。
3. 每条语法输出表格：
   | 语法点 | 项目位置 | 作用 | PHP/Go 类比 | 易错点 | 最小示例 | 本项目用法 |
4. 将语法分为：
   - Kotlin 基础：val/var、data class、sealed class、object、companion object、扩展函数、lambda、高阶函数、空安全、作用域函数等；
   - Android 基础：Activity/Fragment 生命周期、Intent、ViewModel、LiveData/StateFlow、RecyclerView、Compose 等；
   - 并发：协程、suspend、launch、async、Flow、Dispatchers、作用域；
   - 架构：Hilt/Koin、Repository、UseCase、Retrofit、Room；
   - 构建与配置：Gradle、Manifest、权限、资源。
5. 最后给出“我还需要优先补课的 10 个语法点”，并说明每个语法点对应哪个业务模块。
```

## 5. 推荐学习阶段与提示词顺序

可以按下面顺序逐轮让 Agent 生成文档：

### 阶段 1：项目地图与技术栈

让 Agent 输出：

- 目录职责；
- 模块边界；
- 依赖关系；
- 启动入口；
- 页面导航；
- 技术栈速览。

### 阶段 2：Kotlin / Android 语法最小集

只学项目中出现的语法，不系统学完整 Kotlin。要求每条语法配 PHP/Go 类比。

### 阶段 3：启动流程与页面框架

从 `AndroidManifest.xml` 的 Launcher Activity 或 Navigation 入口开始，理解：

- Application；
- Activity；
- Fragment / Composable；
- ViewModel 的创建顺序；
- 页面跳转和参数传递。

### 阶段 4：按业务垂直切片分析核心模块

一次一个业务功能，例如：

- 登录；
- 首页；
- 列表；
- 详情；
- 支付。

每个模块都输出：

- 入口；
- 调用链；
- 数据流；
- 状态；
- 异常；
- 语法卡片；
- 自测题。

### 阶段 5：横切能力专项

分析：

- 网络层 Retrofit / OkHttp；
- 数据层 Room；
- 依赖注入 Hilt / Koin；
- 协程与 Flow；
- 错误处理；
- 日志；
- 权限；
- 配置环境。

### 阶段 6：自测与复盘

让 Agent：

- 出综合题；
- 让你画调用链；
- 让你口述业务流程；
- 批改你的答案；
- 维护 `学习状态.md`：已掌握、待确认、下轮建议。

## 6. 关键技巧

- **先给材料再提问**：至少提供 `tree -L 4`、`settings.gradle`、`build.gradle`、`AndroidManifest.xml`、DI 配置、网络/数据库配置、核心模块源码。若 Agent 不能读仓库，就分批粘贴文件。
- **要求引用路径和行号**：防止它编造业务逻辑。
- **按业务功能分析，而不是按包名分析**：后端程序员更容易从“登录流程、订单列表、支付”切入。
- **让它维护学习状态**：每轮末尾输出“已学/未学/下轮建议”，后续提示词带上状态，避免上下文漂移。
- **不要一次喂整个项目**：每次一个模块，先让它列阅读顺序，再解释代码。
- **每次学完必须自测**：让 Agent 出 5 道题并批改，确保不是“看懂了”的错觉。
- **注意代码安全**：公司项目若不允许上传外部模型，使用本地模型或脱敏后的代码片段。
